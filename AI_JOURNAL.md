# Журнал использования искусственного интеллекта

Архитектура, игровая логика, база данных, серверная часть была спроектирована и написана самостоятельно. ИИ использовался точечно — для ускорения рутинных задач, отладки и генерации вспомогательных элементов (CSS, SVG, тексты).

В процессе работы использовала три разных инструмента на разных этапах.

---

## DeepSeek (начальный этап, без интеграции в код)

На старте использовала DeepSeek в браузере — просто как чат, без подключения к редактору. Помогал разобраться с концепцией и структурой проекта.

| Промпт | Что получила |
|--------|--------------|
| «Как вообще устроена мировая экономика в играх, какие показатели обычно используют?» | Общее понимание каких параметров брать для стран — ВВП, долг, инфляция, резервы. Конкретные числа и структуру придумывала сама. |
| «Объясни как работает эффект заражения в экономике» | Разобралась с идеей распространения кризиса через торговые связи. Механику BFS писала сама. |
| «Какие типы экономических атак бывают в реальности?» | Дал список идей — часть взяла, часть придумала сама, итоговые 6 атак формулировала самостоятельно. |
| «Как хранить состояние игры между сессиями в Python?» | Узнала про SQLite как простой вариант без отдельного сервера. Реализацию писала сама. |
| «Помоги придумать механику раскрытия операции» | Обсудили идею счётчика 0–100%, детали (как растёт, как спадает, что происходит при 100%) придумала сама. |

## Cline (средний этап, интеграция в VS Code)

Cline подключён прямо в редакторе, может читать файлы и писать код в проект. Использовала активнее — помогал с конкретными кусками кода.

| Промпт | Что получила |
|--------|--------------|
| «Напиши SQL-схему для таблиц users и game_states» | Сгенерирована структура `CREATE TABLE` в `users_db_sqlite.py`. Функции `add_user`, `check_user`, `save_game_state`, `load_game_state` и логику работы с базой писала сама. |
| «Почему CORS-ошибка когда фронт обращается к Flask?» | Объяснил проблему, подсказал `flask-cors`. Строчку `CORS(app)` добавила сама. |
| «Напиши CSS тёмного интерфейса в стиле военного терминала» | Сгенерированы `App.css` и `GamePage.css` — анимации, сетка, шрифты, вся вёрстка компонентов. Подбирала цвета под свой вкус. |
| «Как реализовать force-directed граф на SVG без d3?» | Сгенерирован алгоритм физической симуляции — функция `tick` с силами отталкивания и пружинами, логика рёбер, боковая панель с показателями, цветовое кодирование альянсов (`ALLIANCE_COLORS`). |
| «Как хешировать пароль прямо в браузере?» | Получила функцию `hashPassword` через Web Crypto API (`crypto.subtle.digest`). Решение использовать SHA-256 на клиенте принимала сама; сервер хеширует повторно через `hashlib.sha256`. |
| «Как подключить react-svg-worldmap и красить страны?» | Сгенерирован код `styleFunction` с логикой цветов по здоровью, подсветкой выбранной страны и эффектами коллапса. |
| «Как настроить recharts ScatterChart с референсной линией?» | Синтаксис `<ScatterChart>`, `<ZAxis>`, `<ReferenceLine>`. Идея использовать диаграмму в стиле Рейнхарт–Рогофф (долг/ВВП по оси X, здоровье по Y, размер пузырька = ВВП) — самостоятельно. |
| «Подбери реальные данные по ВВП и долгу для нескольких стран» | Проверил порядок цифр для США, Японии, Германии. Структуру `balance.json`, данные по всем 16 странам, альянсы, торговые блоки, энергетические и долговые связи делала сама. |

| «Как развернуть Flask на Render с переменной PORT?» | Объяснил `os.environ.get("PORT", 5003)` и `host="0.0.0.0"`. Деплой на Render и Vercel, настройку переменных окружения делала сама. |
| «Проверь формат вопросов квиза» | Проверил структуру словаря (`question`, `options`, `answer`, `hint`, `explanation`). | «Помоги написать структуру для исторических кейсов к атакам» | Предложил формат объекта `REAL_CASES` с полями `title` и `text`. Все 12 исторических кейсов (2 на каждую из 6 атак: Чёрная среда, Азиатский кризис, Греция, Аргентина, Россия–SWIFT, Иран, Северный поток, Украина 2009, Жёлтые жилеты, Чили, Colonial Pipeline, Эстония) — писала сама. |
| «Помоги отформатировать README» | Выровнял стиль markdown. Содержание обеих частей README (для пользователя и для разработчика) писала сама. |

## Что сделано самостоятельно

- Концепция игры и все механики: 6 атак с разными условиями, распространение кризиса через BFS, раскрытие, квиз, восстановление стран
- Классы `Country`, `Attack`, `GlobalEconomyGame` и все их методы
- Механика распространения урона через граф: разные коэффициенты для торговли (×0.45), долга (×0.5), энергии (×0.6), альянсов (×0.3) и затухание на каждой волне (×0.5)
- Механика защиты: резервы снижают финансовые атаки, альянсы снижают профильные атаки (G7 защищает от валюты, ЕС от энергии, Five Eyes от кибера), торговые блоки ускоряют восстановление, ИЧР даёт бонус к регенерации
- Граф восстановления по зонам здоровья: выше 60% растёт, 40–60% медленно восстанавливается, 20–40% падает, ниже 20% — каскадный коллапс
- Файл `balance.json` — данные по 16 странам: реальные показатели долга, инфляции, безработицы, резервов, энергозависимости, цифровизации, ИЧР, ИКВ; торговые партнёры с долями; держатели долга с суммами; энергетические зависимости; альянсы; торговые блоки
- Образовательные тексты в `lessons.py` — 6 типов атак × несколько сценариев = ~20 уникальных объяснений с шаблонными переменными
- Все 12 реальных исторических кейсов (2 на атаку): Чёрная среда, Азиатский кризис, Греция, Аргентина, Россия–SWIFT, Иран, Северный поток, Украина 2009, Жёлтые жилеты, Чили, Colonial Pipeline, Эстония
- Глоссарий из 8 экономических терминов с подробными объяснениями и числовыми порогами
- Функция `computeAttackConditions()` — подсказки по эффективности атак, показывает текущие цифры выбранной страны
- Функция `getVulnerabilities()` — список уязвимостей страны для боковой панели
- Все 49 вопросов квиза: формулировки, варианты ответов, подсказки, образовательные объяснения
- Паттерн `get_or_create_game()` в Flask: сначала в памяти, потом из базы, потом создаёт новую
- Эндпоинт сброса игры `/reset_game` — удаляет из базы, создаёт свежую
- Брифинг при первом входе (миссионный экран «Совершенно секретно»)
- Деплой на Render (бэкенд) и Vercel (фронтенд)
